# ADR-0019: 公开作品原图存私有对象存储，按权限经服务端代理交付

- Status: accepted
- Date: 2026-09-06
- Refines: D13, D49, ADR-0005（备份桶保留策略）, ADR-0015, ADR-0018

## Context

引用的豆社作品在引用者手里只有冻结图纸，没有原图，因此无法再裁剪、改格数或改颜色数。用户决定：公开作品必须附带原图，引用者也要能拿到原图继续调参；同时私人设计仍然不上传原图（D13 的这一半保留）。

## Decision

1. 原图是作品修订的附属对象，存于**私有** COS 桶，键为 `originals/<revisionId>/<sha256>.<ext>`；数据库 `community_originals` 只记录键、摘要、尺寸与生命周期时间戳，不存字节。默认与数据库备份共用同一个桶（`COS_BUCKET`，备份在 `doupu-backup/` 前缀），只在需要时用 `COS_ORIGINALS_*` 单独分桶 / 换子账号。共用的前提是桶上**不配任何自动删除的生命周期规则**：原图的删除全部由应用按作品生命周期执行，ADR-0005 的「备份 30 天自动过期」改为人工定期清理 `doupu-backup/`。曾考虑强制独立桶以隔离桶级设置，但运维只想维护一套桶与凭证，且前缀已足够隔离键空间，风险点只剩生命周期规则一项，故以文档与部署清单约束而非强制分桶。
2. 上传与下载都经 Next.js Route Handler 代理（`PUT/GET/HEAD /api/community/revisions/[id]/original`），不生成预签名 URL，也不让浏览器直连桶：凭证只在服务端一处，CSP `connect-src` 不需放行第三方域名，鉴权与业务事实在同一进程内判定。上传按魔数嗅探类型并复用现有图片校验（大小、尺寸、动图）。
3. 访问资格：审核员/管理员（含封禁期间）、作品作者、以及 `community_reuses` 中有该修订引用记录的用户；其余一律 404，不区分「不存在」与「无权限」。
4. 提交审核与官方发布前校验原图存在（`ORIGINAL_REQUIRED`）。修改再投稿默认沿用上一版原图（复制行、共享对象键），作者可在提交前替换。
5. 生命周期：作者撤回、驳回、注销 → 事务内标记 `deleted_at`，提交后尽力删除对象，维护任务补扫（`purged_at`）；被新版替代的修订仅在无引用记录时删除；管理员下架 → `blocked_at` 封禁，恢复即解封，30 天未恢复由维护任务删除。对象删除前按键计数，被其它未删除行共享的对象不删。
6. 交付到浏览器：引用成功后客户端拉取原图并通过一次性 IndexedDB 交接库带进工作台，工作台把原图绑定到刚恢复的副本（不重新生成，保留作者手工修补），同时产生 800px 生成源随下次保存落盘；之后两份图纸互不联动。作者本人从工作台「公开到豆社」时也用同一交接库把会话原图带到投稿页。

## Consequences

- D13 的「原图不上传云端」收窄为「私人设计的原图不上传」；隐私政策、关于页与官方批量说明同步改写，投稿页新增明确的上传同意。
- 缺 COS 配置（桶、凭证、地域任一）时生产拒绝启动；开发与 E2E 落到本机目录实现同一接口，测试用内存实现。
- 备份与原图同桶后，任何整桶或无前缀限定的过期 / 清理操作都会连带删除用户原图（原图没有第二份副本）；部署清单要求核对现有桶没有此类规则，人工清理备份只在 `doupu-backup/` 前缀下操作。
- 已引用者本机的副本无法追回，这是用户接受的边界并写入隐私政策。
- 换设备打开引用副本时，本轮只在同一浏览器记录了来源修订，「从豆社取回原图」入口在其他设备上不显示；后续可把来源修订随云端设计元数据下发。
