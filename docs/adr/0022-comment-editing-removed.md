# ADR-0022: 评论只能发表与删除，移除编辑能力

- Status: accepted
- Date: 2026-09-07
- Refines: D50, ADR-0020

## Context

评论原本允许作者在发布后 15 分钟内编辑，编辑再次走内容安全管线，高风险修改转待审、被拦截时保留旧正文。用户在 R12 验收时明确表示评论不需要编辑：图纸讨论都是短句，编辑窗口带来的状态机（发布时间起点、重新审核、版本冲突、治理台看到的是覆盖后的正文）远多于它的价值，也让治理记录难以对应原文。

## Decision

1. 删除评论编辑：前端不再有「编辑 / 保存修改」入口，`PATCH /api/community/comments/[id]` 路由与 `editCommunityComment()` 服务移除，审核管线不再需要 `excludeCommentId`，埋点 `community_comment_edited` 退役。
2. 评论仍可由作者删除（软删除，正文清空），删除前须二次确认；治理台的隐藏 / 复核后公开不受影响。
3. 数据库不做破坏性迁移：`community_comments.edited_at` 停写保留（可空列），`published_at` 继续作为「进入公开态」的展示与审计时间戳；历史数据中已有的 `edited_at` 值只读保留。
4. 术语「评论发布时间」改为纯展示 / 审计语义；隐私政策中「发表或修改评论」改为「发表评论」。

## Consequences

- 想改评论的作者只能删除后重发；重发会重新走限流与内容安全判定，正是希望的行为。
- 治理台看到的正文即作者发出的原文，举报与判定记录不再存在「原文已被覆盖」的歧义。
- 若未来重新需要编辑，应设计为「新版本 + 旧版本只读保留」，而不是覆盖正文。
