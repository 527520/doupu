# ADR-0020: 评论审核外部化到腾讯云文本内容安全，带成本护栏与审计

- Status: accepted
- Date: 2026-09-06
- Supersedes: 审核规则版本（字面词表）机制；Refines: D50

## Context

原有评论审核依赖管理员维护的字面词版本表，初始只有八个词，实际防护力很弱。开源中文敏感词库几乎都内含政治词，与本项目「不自行维护政治词库」的边界冲突且许可与维护状况参差。用户决定采用腾讯云文本内容安全（`TextModeration`），但要求严格防刷、控制成本，并且每次判定都留审计。

## Decision

1. 管线固定为：本地结构检查（多链接、控制字符、超长重复）→ 反刷闸门（每账号每小时/每天、每 IP 每小时、5 分钟内突发与重复）→ 同文哈希缓存（默认 7 天）→ 全站日预算 → 真实调用（3 秒超时）。前四步不花钱；只有走到最后一步才计费。
2. 判定映射：`Pass` 直接公开；`Review` 进入人工待审；`Block` 拒绝——评论仍以新增的 `rejected` 状态落库，正文只在评论治理台可见，可由审核员填写理由后「复核后公开」。编辑被拦截时保留原公开正文不变。
3. 任何不可用（未配置、鉴权失败、限流、超时、超预算）都转人工待审，绝不静默公开；系统信息页展示当日调用、缓存命中、本地判定、失败与最近错误。
4. 每次判定写 `comment_moderation_checks`：来源、建议、标签、置信度、命中词、腾讯云 RequestId、耗时、结果与依据；不保存正文（正文在评论表）。限流拒绝也留痕但不创建评论；为此拒绝/限流的错误在事务提交之后抛出。
5. 上送内容只含评论文本、我们的记录 ID 和公开作者 ID 的不可逆哈希；不含邮箱、内部 userId 或 IP。
6. 阈值全部走集中配置（D32）：`TMS_DAILY_BUDGET`、`TMS_CACHE_HOURS`、`TMS_TIMEOUT_MS`、`RATE_COMMENT_*`。
7. 旧的 `/admin/rules` 页面、API、编辑器与 `moderation-rules:manage` 能力删除；`moderation_rule_set_versions` 表只读保留历史。

## Consequences

- 词表维护工作消失；代价是每条真实判定有费用，靠限流、缓存与日预算封顶。
- 开发与 E2E 不访问腾讯云：启动种子安装确定性的假服务（含「E2E风险词」建议复核、含「E2E拦截词」拦截），单测通过注入 `moderate` 覆盖三种建议与失败路径。
- 社区规范与隐私政策写明评论文本会送第三方服务判定并保留判定记录。
