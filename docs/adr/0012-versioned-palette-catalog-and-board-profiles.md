# ADR-0012: Versioned palette catalog and physical board profiles

- Status: accepted
- Date: 2026-08-30
- Supersedes: CONTEXT.md D3, D16, D17 and D21; ADR-0011's fixed 29×29 board partition
- Refines: CONTEXT.md D6, D39, D42, D43 and D44

## Context

豆谱最初把五个品牌名直接映射到同一份 291 行兼容矩阵，并假定所有图纸都使用
5 mm 豆与 29×29 底板。这让旧项目具有稳定结果，但无法同时表达同一品牌的不同
系列、来源质量和真实可生成颜色数，也无法正确导出或跟拼 2.6 mm Mini 底板。

外部仓库 `HansBug/pindou-color-data` 收录了更多色卡，但其中同时存在不同来源版本、
透明材质、待核对或缺失色号、重复 RGB，以及不应作为独立产品展示的合并表和旧表。
若调用方各自解释这些数据，生成结果、色板页和项目恢复可能使用不同的过滤规则；若运行
时跟踪上游最新版，同一个持久化色板 ID 的含义还会随时间变化。

制作规格也是持久化业务数据，而不是纯显示选项。29、50 与 52 决定板缝、跟拼分板、
尺寸快捷档和导出几何；50×50 与 52×52 的 2.6 mm 底板钉距体系不能视为同一种规格。

## Decision

- `src/lib/palettes` 是内置色板的唯一目录边界。调用方只通过列表、稳定 ID 解析和引擎
  颜色投影取数，不自行解析来源格式或重复过滤数据。内置目录摘要还为每个品牌明确且唯一地
  标记默认系列；品牌/系列选择器不得从版本化 ID 或数组顺序推断默认值。“我的色板”没有
  目录默认项：选择器在会话内优先恢复该组上次明确选择的色板；从未选择过时只展开系列列表，
  必须由用户明确选择系列后才改变项目色板。
- 用户可见 13 套色板：五套原有 MARD、COCO、漫漫、盼盼与咪小窝豆谱经典版，
  以及 MARD 291、COCO 291、漫漫 278、盼盼 289、咪小窝 290、MARD 221 核对版、
  Artkal C 197 与 Artkal M 221。重复的 MARD 221 源码版、Artkal C+M 418 合并表和
  Artkal 174 旧表不进入目录。
- 五套经典版拆成五个锁定数据文件，品牌短 ID 永久指向这些经典版，
  MARD 经典 291 色继续作为默认色板。漫漫经典版将 `#F3C1C0` 的重复色号由 `S4`
  明示纠正为 `S7`；该纠错不改变 HEX 或顺序，但不保留命中此颜色的旧生成 golden。
- 八套外部数据固定在 `HansBug/pindou-color-data` 提交
  `178dafbc9e77d3de556550dbd058270200129186`。应用内只包含经过显式导入校验的最小快照、
  来源和许可记录；构建与运行时均不访问 GitHub，也不自动追踪新提交。外部持久化 ID
  包含该来源版本；未来数据修订必须创建新 ID。
- 完整展示数据保留不可生成项及其原因。引擎投影排除透明/RGBA、`unidentified`、
  `UNKNOWN-*`、空色号和非法 HEX；重复 HEX 按上游顺序只让第一个色号参与生成，后续
  色号作为可追溯别名展示。有真实色号的荧光、珠光等材质可以匹配，但屏幕 RGB 只作
  近似参考，不能代替实物色卡。
- 制作规格使用稳定 ID：`5mm-29`、`2.6mm-50`、`2.6mm-52`。Artkal C/M 只允许两种
  2.6 mm 规格；MARD 221 允许三种；其余内置色板只允许 `5mm-29`；自定义色板允许三种。
  选择与当前规格不兼容的色板时，在一次可撤销变更中同时切换到其默认规格：Artkal
  使用 `2.6mm-50`，其他色板使用 `5mm-29`。
- 板行列数与 PDF 单元格尺寸由制作规格模块统一提供，并贯穿空白起稿、板缝、编辑定位、
  跟拼、PNG 与 PDF。5 mm PDF 保留原版式；2.6 mm PDF 使用 2.6 mm 单元格，每页对应
  一块 50×50 或 52×52 底板。
- `ProjectFile v3` 始终写入顶层 `boardProfile`，并以必填的
  `paletteSelection { palette, kitTier }` 原子保存色板定义与套装档位。解析器只接受严格
  v3，v1/v2、未知字段、未知色板/规格及不可用档位均明确拒绝，不补默认值。分享快照使用
  独立的严格 v3，仅保存名称、创建时间、规格、色板定义与图纸，不保存套装档位或生成参数。
  当前没有用户或历史分享，测试数据在发布环境外显式清理；应用不保留迁移或自动清库分支。
  IndexedDB、同步数据库、revision CAS 与本地生成源的表结构不因本决策升级。
- 本决策不改变 Oklab、量化、抖动、采样、背景识别或颜色合并算法。

## Alternatives considered

- **运行时直接读取 GitHub 或自动跟踪最新版。** 拒绝：可用性依赖网络，也会让同一项目
  在不同时间恢复出不同颜色；上游变化必须先经人工审查并发布新的稳定 ID。
- **把同品牌外部数据覆盖到旧短 ID。** 拒绝：会破坏既有项目、默认结果和缓存键；同名
  系列必须通过不同 ID 明确区分。
- **让每个调用方自行过滤色板。** 拒绝：页面展示、引擎、编辑器与导出会产生不一致，
  也可能把透明或未知色号伪装成可采购颜色。
- **把两种 Mini 底板合并为一个 `2.6mm` 选项。** 拒绝：50 与 52 的板缝和物理钉距
  不兼容，合并会生成无法按用户底板准确跟拼或打印的图纸。
- **继续沿用 v2 并为缺失字段补默认值。** 拒绝：同一版本将出现两种不等价结构，且会
  永久保留无真实用户需要的兼容分支。v3 让色板选择、套装档位与制作规格成为明确的不变量。

## Consequences

- 色板名称、收录数与可生成数可能不同。用户界面必须同时展示两者、来源质量、排除项和
  适用规格；“全部颜色”与套装档位必须按当前 `engineColors` 动态计算。
- 项目、云端同步和分享必须保留稳定色板 ID 与制作规格。单独改变制作规格不应改变图纸
  格子、统计或生成算法结果，只改变物理分板与导出几何。
- v3 项目与分享必须由同一版本站点整体发布；旧测试数据和旧导出文件不会被读取，也不会
  在运行时静默迁移。清理测试数据是发布操作，不是长期业务代码。发布镜像中的只读协议
  检查器由正式 schema 在构建阶段打包生成，避免部署脚本复制色板和协议校验逻辑。
- 资料色值是数字参考，尤其特殊材质可能与屏幕显示和实物批次有差异；购买前仍应核对
  品牌的实物色卡与所持底板规格。
