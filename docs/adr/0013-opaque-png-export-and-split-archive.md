# ADR-0013: 不透明 PNG 与超限拆分归档

- Status: accepted
- Date: 2026-08-30
- Refines: CONTEXT.md D6 and D32

## Context

透明的图纸空白区和图例背景在部分查看器中会变成黑底，色号难以阅读。大图纸若继续把
图纸与大量图例塞进同一 Canvas，则可能超过浏览器可靠尺寸或产生不可接受的瞬时内存；
静默缩小图例又会让导出结果失去制作价值。

## Decision

- UI 预检与实际绘制共用纯 `PngExportPlan`，使用同一份内容范围、图例排版和 Canvas 上限。
- 每张导出 Canvas 创建后先铺满纯白色；透明格、外部格、图纸间隙与图例区最终均不透明。
- 图例字号、色块和行高有独立可读下限，不随图纸格子无限缩小。
- Canvas 边长与总像素上限是 Chromium、Firefox、WebKit 可靠交集形成的领域安全不变量，
  不提供环境变量绕过。图纸本身超限时明确拒绝，并提示降低格子尺寸或改用分页 PDF。
- 合并画布超限、但图纸与图例分别合法时，导出两张 PNG，并在下载层按需加载
  `client-zip` 打成一个 ZIP；不得为维持单文件而缩小图例。文件名文案统一来自中文消息表。

## Consequences

- PNG 单文件与 ZIP 都必须验证可解码、完整图例和 alpha 全为 255；ZIP 恰好包含图纸与图例。
- ZIP 只是浏览器下载 artifact，不进入项目文件、分享快照、数据库或同步协议。
- 调整浏览器安全上限需要跨三引擎及目标真机重新验收，并更新本 ADR 的依据。
